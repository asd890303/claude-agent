# 程式碼慣例

跨專案通用的實作習慣。專案有自己的 `CLAUDE.md`／規則時，以專案規則優先。

## 一、禁止 magic number / magic string

- 狀態值、模式旗標的比較、顯示、篩選，一律用 **enum 或具名常數**，禁止散落魔術數字（如 `status === 1`）
- 「狀態 → 顏色／文案」這類顯示對應集中在**單一 helper**，不在各頁面各處重複自建 map（DRY）

## 二、enum / 狀態值不擅自新增

- 需要的值在 enum 裡沒有時，**不得擅自新增**——先與後端或使用者確認（可能是尚未同步，也可能是誤用）
- 確認要新增時，把所有相依處**一次補齊**（定義、顯示對應、翻譯、篩選選項）
- 有型別窮舉的地方靠編譯器把關；無型別保護處（如翻譯檔）需人工核對，避免漏加後顯示異常

## 三、優先用框架／函式庫的官方作法

- 例如表單驗證用框架內建機制（如 antd Form 的 `rules` + `validateFields()`），不自行手寫等價邏輯
- 送出、重設等流程走統一入口，不在各處各自實作

## 四、命名一致性

- 送出 handler 用語意化命名（`handleSubmit`；多流程加前綴如 `handleWalletSubmit`），避免無語意的 `handleOk` / `handleSave`
- 型別、變數命名反映用途，不用泛稱

## 五、非同步操作的狀態回饋

- 會觸發 API／非同步的 UI 元件一律綁 `loading` / `disabled`，避免重複觸發與無回饋
